## What runs

`wp10f_adapter.c` includes only `engine/include` and uses the public API. It is the #330 binding's
fault-injecting sparse device, durability settling, remounts and duplicate runner
(`tests/wp10_backlog_r54_adapter/wp10r54_adapter.c`), with one addition: a count of every callback
(reads included) and the position of the fired injection. The four row runners are new.
`run_product.py` restates the plan order from `model.py` / `dupmodel.py`. The package's `oracle.py`
is never imported. The restated case set must hash to `159b4ac6…` before anything runs.

- **Rows 1–2.** The fixture image comes from `model.row1_image` / `row2_image`. Mount the listed side
  on a writable device, then make one call: `tape_reset_side_b`, `tape_arm(OVERWRITE)`, or
  `tape_respool(65535)` until `more_work == false`. The runner records every write and flush from
  that call, the whole-image SHA-256 before and after, and `after_raw` (both superblocks and the
  first two blocks of each slot).
- **Row 3.**
  - Pre-state: mount B and render, then mount A and render.
  - Clean run: mount B, then `tape_respool(64)` to completion, recording every callback from those
    calls, reads included, then a Side-B remount and render.
  - Crash runs: for each mode, every clean write at landed 0–512, then every clean flush. Each runs
    on a fresh device, with counters starting at the first re-spool callback. Pending flush-required
    writes survive by the ADAPTER.md bit rule, with ordinal = the crash's position in the fixture's
    list. Then Side B and Side A are remounted and rendered.
- **Row 4.**
  - First run: `tape_dup` onto `dupmodel.rerun_destination(shape)`, injected at the
    representative's point.
  - The same destination, holding only its durable bytes, gets a re-run injected at the case's
    point.
  - Settling uses ordinal = case index. Then `ro_A`, `rw_A` and `rw_B` remounts, as in #105/#330.
  - The source is #330's `src128`. Its image hash is recomputed after the run only if a write
    reached it; none did.

## Run

    make -C engine clean all
    make -C tests/wp10_final_adapter clean all
    python3 tests/wp10_final_adapter/run_product.py --evidence <fresh dir> \
        --retained tests/wp10_final_adapter/evidence/p1-r55-product
    python3 tests/wp10_final_adapter/run_product.py \
        --replay tests/wp10_final_adapter/evidence/p1-r55-product --out <fresh dir>
    python3 -B tests/wp10_final_adapter/negative_controls.py <dir>/wp10-final-r54-product-observations.jsonl.gz

`negative_controls.py` is non-canonical. It prints the per-row census and the V-R54-03 count. It then
requires the oracle to reject single-fact mutations of passing Product observations:

- rows 1–2: a wrong result, a write on a refusal, and a changed Side A slot;
- row 3: wrong post-crash audio, a missing crash record, and changed Side A audio;
- row 4: the trace, durable bytes, a written source, and the first-run state.
