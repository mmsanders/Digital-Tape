# R29-A promote product-binding contract

This directory is an independent verifier-owned DRAFT-8 package for Digital-Tape-Verification issue #70. A later Software round may import the exact publication tree byte-for-byte and add only a mechanical binding.

The product adapter may emit raw media bytes, direct public API results, opaque operation tokens, numeric progress/callback counters, exact call arguments, exact block callback traces, raw render bytes, raw position-table values, and raw counter values. It may not emit verifier conclusions.

The verifier recursively rejects pre-disposed fields such as operation-running, work-advanced, state-changed, recursion/no-recursion, audio-continues, source-faulted, row-matched, positions-cleared, headroom-ok, completed, or no-second-copy judgments.

## Blindness boundary

The verifier package is authored only from the frozen authority named in README.md and COVERAGE.md. Product implementation must not be consulted to alter fixtures, target order, planner membership, outcome logic, or the raw observation schema.

## Handshake

The production adapter starts once and emits one JSON object:

- `format: PROMOTE-ADAPTER-1`
- `adapter_kind: product`
- stable non-empty `adapter_id`
- `caseset_sha256: 8732af9434437d0411731b3e4909a2ca9a1278778e5d9c8947642cec7b793442`
- `raw_observation_only: true`

The verifier then streams all 44,311 canonical cases in order. There is no production sampling, case-count override, durability override, torn-length override, or phase override.

## Verifier-owned media

The crash fixtures are generated by fixture.py. They use ordinary byte-exact DRAFT-8 superblocks and index headers.

The promoted timeline is deliberately exactly **128 stereo frames = 512 bytes**. DRAFT-8 §6 says bytes after the referenced part of a partially written chunk are undefined. Therefore a compact copy of this timeline has exactly one required chunk-data block write. This is not sampling a larger chunk copy: it is a complete valid one-block timeline chosen so every relevant write boundary in the scripted promote can be exhaustively torn 1…511 bytes.

The principal allocating fixture has:

- old Side A at chunk 0;
- a fragmented Side B whose 128 frames are split across chunks 1 and 2;
- `a_high_water = 2`;
- `free_next = 3`;
- shared cartridge sequence base 500;
- a full promote path that stages at chunk 3 and then compacts to chunk 0.

The adopt-in-place fixture has an already-compacted B run at chunk 3 and exact tail capacity. The first-use fixture models format → first recording into B at chunk 0 → promote, giving `S == 0`.

## Crash observation

For every crash case emit `PROMOTE-OBSERVATION-1` containing:

- verifier case index and scope;
- `injection_fired=true`;
- exact verifier-format `pre_snapshot`;
- exact durable-only `post_snapshot`;
- the clean `target_baseline`;
- fresh product mount result for Side A and Side B;
- SHA-256 of the raw rendered PCM for each side that mounts successfully.

A snapshot contains:

- primary and mirror superblock blocks;
- block 0 and block 1 of A0/A1/B0/B1;
- the exact first 512-byte audio block of every fixture chunk.

Those bytes are sufficient for every verifier fixture because all referenced audio lies within that first block.

The verifier independently parses CRCs, selects superblocks and index slots, enforces Side-A water-line validity and interval disjointness, applies the §9.3.3 stage oracle, checks the global structural `sequence` uniqueness rule, and reconstructs the referenced PCM.

## Fault device / durability

Keep separate **working** and **durable** block images.

- reads observe working bytes;
- a successful write changes working;
- write-through also changes durable immediately;
- flush-required changes durable only when flush succeeds;
- a successful flush makes all prior working writes durable;
- a crash discards working state and remounts a fresh engine from durable bytes only.

Every targeted one-block write gets:

- before write: 0 bytes landed;
- torn prefixes 1…511;
- after complete write: 512 bytes landed before the following flush;
- failure/power loss at that following flush.

A torn prefix changes that prefix in both working and durable media and then fails the write. An after-write cut is not a 512-byte torn write: on flush-required media it is still non-durable.

## Adopt-in-place path

The exact-tail fixture begins with Side B as one compact run at chunk 3. Phase 1 therefore skips the data copy and step 3. The 11 target writes are step 2, step 4, phase-2 data, step 7, step 8, step 9.

A product adapter must expose the actual block callback trace. Verification, not Software, decides whether an unnecessary second staging copy occurred.

## First-use S == 0 path

The first-use fixture starts from the raw state produced by a formatted cartridge after one 128-frame recording on B at chunk 0.

Adopt-in-place chooses `S=0`, skips phase-1 copy and step 3, commits A, writes step 4, and step 5 must decline because `[0,len)` intersects the live set.

The six targets are:

- step-2 entry block;
- step-2 header;
- step-4 partner;
- step-4 candidate;
- step-5-decline partner;
- step-5-decline candidate.

Whenever stage 1 is selected between steps 4 and 6, the raw media must match exactly §9.3.3 row 1. Rows 2 and 3 are forbidden by their `S > 0` guards.

## Two-interruption closure

For step 4, step-5 decline, and step 9 separately, fixture.py creates four permitted recovery seeds:

1. current primary only;
2. current mirror only;
3. current primary plus stale lower-generation mirror;
4. current mirror plus stale lower-generation primary.

The setup state is raw verifier-owned media. The second interruption targets the next §4.6 **partner** write, with before/1…511/after and partner-flush cuts in both durability modes.

Verification independently selects the durable superblock and rejects any rollback below the pre-update current generation.

## Rerun from all eleven §9.3.4 rows

The planner has one rerun case for every recovery-table row. The adapter receives the exact verifier seed for that row and emits:

- exact seed snapshot;
- public promote result;
- chronological block callback trace;
- terminal raw snapshot.

The verifier counts raw chunk-region writes and checks terminal raw media.

Expected new compact-copy counts on the rerun are:

- rows 1–2: 2 data-block copies;
- rows 3–6: 1;
- rows 7–11: 0.

The exact-tail case is row 4 on a four-chunk cartridge. It must finish with only the low phase-2 copy; a `TAPE_ERR_CARTRIDGE_FULL` is a failure.

The repeated row-4 case emits raw staging starts, `free_next` values, and chunk-write LBAs across at least three retries. Verification derives whether successive staging runs were consumed.

## Stored positions

For full path, step-5 decline, resume at step 8, resume at step 9, and NOTHING-TO-DO, emit the raw device-side position-table values after every promote call.

Verification requires A/B entries to remain unchanged on every `more_work=true` continuation and to be absent/cleared only on the terminal `TAPE_OK, more_work=false` call.

## Branch-exact headroom

For every §4.5 promote branch, expose the raw starting `cartridge_sequence`, `sb_generation`, public result, and block trace. The verifier computes the exact per-branch needs:

| Branch | sequence | sb_generation |
|---|---:|---:|
| fresh allocating, S≥len | 4 | 2 |
| fresh allocating, S<len | 2 | 2 |
| fresh adopt, S≥len | 3 | 2 |
| fresh adopt, S<len | 1 | 2 |
| resume step 5, S≥len | 2 | 1 |
| resume step 5, S<len | 0 | 1 |
| resume step 8 | 1 | 1 |
| resume step 9 | 0 | 1 |
| NOTHING TO DO | 0 | 0 |

The canonical cases include exact-boundary success, one-short refusal independently for each non-zero counter requirement, FRESH decline at sequence 0xFFFFFFFB, RESUME-decline at 0xFFFFFFFC, the historical FRESH-allocating 0xFFFFFFFC hazard, and zero-needed NOTHING-TO-DO at 0xFFFFFFFE/0xFFFFFFFF for each counter.

A refusing case must emit an empty block trace.

## Shared sequence / counter domains

The shared-sequence case exposes all four structurally valid starting sequences: A=10/9, B=500/499. Verification requires promote commits 501, 502, 503, 504.

The counter-domain case exposes before/after numeric values proving that an index-only commit advances sequence but not `sb_generation`, while a superblock-only update advances `sb_generation` but not sequence.

## Promote WP-12a row

An in-progress operation snapshot contains only:

- opaque `operation_token`;
- exact numeric `progress_blocks`;
- exact cumulative own-device event count.

For all fifteen matrix columns, expose that snapshot before/after, exact public result, and exact block trace.

The eleven BUSY columns are followed by an ordinary promote continuation with raw before/after snapshots. Verification derives no-work-on-BUSY, operation survival, forward progress, and no restart.

Render exposes rendered count and exact PCM bytes. Service exposes its block trace. The grouped status/info/tell cell exposes all three public results.

Zero-budget cases expose the same raw snapshots and block trace. Promote has no fixed continuation arguments beyond the instance itself; its allowed mutable arguments are exactly block_budget, more_work pointer, callback, and user pointer, and the allowed-mutables case changes all four while exposing raw progress.

## Own-device fault / FAULTED row

For an own-device write/flush failure on continuation emit:

- pre-failure transport and operation snapshot;
- exact failing callback event and raw return code;
- promote result and `more_work`;
- post-call transport state.

Verification requires the I/O error to terminate the operation and put the instance in FAULTED.

Then exercise all fifteen Faulted-row columns. The eleven forbidden calls must expose `TAPE_ERR_FAULTED` and an empty block trace. The four allowed matrix cells are render, status/info/tell, abort, and unmount.

For render, expose successive ring frame counts, results, rendered counts and raw output through the final underrun. For abort, expose raw `frames_owed` before/after, the armed-state fact, and an empty block trace. This lets Verification derive ring drain, abort cleanup, and Faulted precedence over armed state.

## Callback re-entry

For every matrix column, from inside a progress callback emit:

- operation snapshot before/after nested call;
- callback entry count;
- maximum callback depth;
- nested public result and block trace;
- next ordinary continuation before/after snapshots.

Render and status/info/tell remain allowed. Every other same-instance call, including matching promote and service, must return BUSY. Verification derives no recursion/state mutation and survival of the original operation.

## Small-budget completion

Emit the ordered sequence of every promote call:

- function identity;
- budget;
- result;
- `more_work`;
- opaque operation token;
- progress before/after.

Also emit terminal raw media. Verification derives same-function continuation, at least one nonterminal call, one terminal call, token continuity, forward progress, and final promoted layout.

## Failure retention

On first failure retain `failure-reproducer.json` with the canonical case, exact promote phase, injection coordinate, pre/post durable snapshots and actual A/B remount results.

Success evidence retains the exact census/digest, product commit/tree, verifier publication/tree, adapter source/build hashes, stderr, and summary hash. A Software green is evidence only; it is not a Verification disposition.
