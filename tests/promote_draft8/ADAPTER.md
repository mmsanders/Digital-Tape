# Mechanical product adapter contract

The verifier invokes:

`wp_promote_probe CASE_ID INPUT.vo08 OUTPUT.vo08`

The case IDs are the 16 rows generated by `oracle.make_cases()`.

`INPUT.vo08` contains the exact verifier-authored superblocks and four index
slots. Prepare the product device from those metadata bytes with deterministic
fixture chunk contents sufficient to execute the requested copy. `OUTPUT.vo08`
must serialize the post-operation superblocks and four index slots in the same
envelope. Chunk payload bytes are intentionally outside this tranche.

Mount Side B for every case **except `PR-DEGRADED`**, which must mount Side A
to obtain the specified degraded-B mounted state. A Side-B mount of that fixture
would correctly fail before `tape_promote` and therefore would not test §9.3.0.

After the setup mount, clear the callback trace. Call `tape_promote` with
`block_budget=64` repeatedly until `more_work == false` or a refusal is
returned, then unmount. Record complete public-call results and the complete
block-device callback trace generated by the promote calls. Setup/teardown mount
I/O is excluded from `events`.

Stdout must contain exactly one JSON object:

```json
{
  "format": "WP-PROMOTE-OBSERVATION-1",
  "case_id": "PR-ADOPT-COMPLETE",
  "adapter_kind": "product",
  "adapter_id": "stable-product-adapter-id",
  "calls": [],
  "events": []
}
```

Each callback event uses `op = read|write|flush`; reads/writes include `lba`
and `count`. Do not filter callbacks. The verifier tolerates arbitrary read
batching, but write destinations and metadata durability order are normative.

The observation's `calls` must include the setup `tape_mount`, every
`tape_promote` invocation with `result`, `more_work` and `block_budget`,
and the final `tape_unmount`.

`adapter_kind=synthetic` is reserved for verifier plumbing. Product evidence
must identify as `product`. Do not change fixture bytes, counter values, mount
side, event filtering or expected results to make a product build pass.

This adapter does not observe the caller-owned stored-position table, so the
terminal-success position-clearing acceptance requirement is explicitly outside
this tranche.
