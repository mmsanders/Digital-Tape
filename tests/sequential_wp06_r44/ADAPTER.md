# WP-06 R44 sequential adapter contract

The Product adapter is a separate executable. Run exactly the cases in `oracle.cases()` against a fresh block file per case at the **issued** Product main `788cb765493096a076603e5ad4ac6e2dea47a7a9` (engine tree `054d27ab6e3e72f61118ff7d99e19e48741d05b2`), or label a later source explicitly. The adapter must not import the oracle or manufacture expected results. Emit one JSON object per case as JSONL. Record the real `tape_*` result and actual public `tape_get_info` fields, every `dev_read`, `dev_write`, `dev_flush` invocation in order (including failed callbacks), and direct raw block reads *outside* the engine at the named snapshots. `step` partitions a call, `ordinal` is a monotonically increasing event number per case, `lba` is integer; don't count observation reads as engine callbacks. Do not report private `phase`, `candidate`, `selected_b` or `free_next` as an observation.

Object: `schema: "wp06-r44-v1"`, `case`, `block_count`, `calls: [{step,fn,result,...public fields only}]`, `events: [{step,op,ordinal,lba?,result?}]`, `snapshots: {name: {primary: hex512, mirror: hex512, A0: hex65536, A1: hex65536, B0: hex65536, B1: hex65536}}`. Capture each **entire** raw index slot, including invalid headers, unused blocks and invalid partners. Capture snapshots even if the engine refuses; a refusal compares every captured byte, not parsed validity. For repair cases use `before`, `after_mount`, `after_retry`; for degraded cases `before`, and on reset `after_reset`, `after_remount`; round-trip cases `after_format`, `after_remount`; refusal cases `before`, `after_mount`. A failed repair callback may or may not leave its target durable; preserve the real file snapshot. Retry with callbacks healthy, unmounting the first instance first. Never reuse an instance across cases.

Step names are fixed in `oracle.check()`: `mount`, `retry`, `probe`, `exercise`, `remount`, `switch`, `format`, `mount1`, `commit`, `unmount`, `mount2`. Use the case family/variant to initialize media: both indices individually valid except specified degradation/refusal; corrupt or stale exactly the named partner; stage mismatch or bad A in refusal cases; Side A nonempty and B absent/equal-divergent for degraded cases. For round trips format a fresh device, mount B, arm/feed/service until owed frames clear, commit, unmount/remount; `max-entries` must exercise 4096 live entries and 96 entry-array blocks before the header. For each successful mount, call `tape_get_info` and report actual `needs_repair`, `side_b_valid`, `free_chunks`, `total_frames`, `uuid` as relevant. The oracle selects candidate and live slot from raw bytes and derives `free_next` from A high-water/live B, checking `free_chunks == total_chunks − free_next`; it derives repair-after-validation from both superblock and four index-header reads preceding the partner write. A commit with accepted frames has chunk writes during `service`, **not** during `commit`. The adapter should record fixture-construction SHA-256 and its source/build command alongside the JSONL; `runner.py` binds its own oracle, plan, input digest, Product SHA/tree and adapter-source digest in a non-overwriting manifest.

The oracle does not grant Product acceptance. A synthetic self-test tests parser/red-control sensitivity only. A Product result needs the real adapter, committed immutable Product source identity and retained unabridged JSONL plus manifest. The public API has no `free_next` or selected-slot field; neither is required as an adapter assertion.
