# WP-07 allocator/COW product binding contract

This package is verifier-owned. A later Software round imports it byte-for-byte under
Structural Rule 1 and supplies only a mechanical adapter around the public engine API
and a virtual block-device callback surface.

Software must not rewrite plans, decide acceptance, suppress block callbacks, parse
indices on the verifier's behalf, or inspect/modify verifier expectations.

## Invocation

The production runner invokes:

```text
allocator_cow_product_adapter \
  --fuzz-fixture FUZZ.vo08 \
  --reset-stress-fixture RESET-STRESS.vo08
```

The two compact VO08 fixtures are generated by verifier-owned `fixture.py`. The
adapter must authenticate/load those exact bytes and use a fresh copy of the fuzz
fixture for every generated sequence.

Immediately after start it emits one JSON line:

```json
{
  "type": "hello",
  "format": "WP07-COW-ADAPTER-1",
  "adapter_kind": "product",
  "fuzz_fixture_sha256": "...",
  "reset_stress_fixture_sha256": "..."
}
```

and flushes stdout.

The verifier then sends exactly one `reset_stress` command followed by exactly
10,000 `sequence` commands from verifier-owned SplitMix64-v1 generation, then
`done`. There is no production count/seed override.

## Raw media snapshots are authoritative

The adapter must not report a guessed/decoded "live index". After every successful
commit/reset + unmount/remount it reads the **raw B0 and B1 slot metadata bytes from
its backing block device** and returns each as:

```json
{"header_hex":"<exact 64 bytes>","entries_hex":"<exact 12*entry_count bytes>"}
```

For a non-index/invalid slot, return its actual first 64 bytes and an empty entries
string. The verifier independently:
- verifies index CRC;
- validates entry counts, totals and bounds;
- checks half-open physical-frame interval disjointness;
- selects B0/B1 under DRAFT-8 §5.3;
- derives `free_next`.

The adapter must also snapshot B0/B1 **immediately before every generated action**.
The verifier requires media continuity between the previous post-action snapshot and
the next pre-action snapshot.

## Complete write-event capture

Every `dev_write` callback during the scoped operation/probe must be recorded before
range/error handling as:

```json
{"lba": <uint32>, "count": <positive uint32>}
```

No write may be omitted, coalesced in a way that loses covered LBAs, filtered because
it targets metadata, or converted into an adapter verdict. If fixed event storage can
overflow, set `event_overflow=true`; the verifier fails closed.

The verifier maps raw LBAs to chunk ids itself.

## Generated edit action

For each verifier `edit` plan:

1. Start from the current successful Side-B remount.
2. Read raw pre-action B0/B1 metadata.
3. Get public `tape_info.total_frames`.
4. Resolve the verifier's symbolic selector exactly:
   - `start = 0`
   - `mid = total_frames // 2`
   - `end = total_frames`
   - `q1 = total_frames // 4`
   - `q3 = 3*total_frames // 4`
   - `cf_half = min(total_frames, 65536)`
   - `cf_boundary = min(total_frames, 131072)`
   - `cf_boundary_minus = min(total_frames, 131071)`
   - `cf_boundary_plus = min(total_frames, 131073)`
5. Call `tape_seek`.
6. Call `tape_arm` with the exact generated mode
   (`OVERWRITE`, `OVERDUB`, or `SPLICE`).
7. Call `tape_feed` with exactly the generated positive frame count and deterministic
   zero PCM. The fixture/campaign is sized so the complete request must be accepted.
8. Repeatedly call `tape_service` with the generated positive block budget until
   frames owed clear. Do not commit early.
9. Call synchronous `tape_commit`.
10. Unmount and remount Side B from frame 0, cold.
11. Return the raw post-remount B0/B1 metadata and public `total_frames`.
12. Run the allocation probe below, then unmount/remount again before the next action.

Return all actual results. The verifier requires TAPE_OK for seek/arm/feed/service
terminal/commit/unmount/remount and `accepted_frames == requested frames` for this
WP-07 campaign. That requirement is campaign plumbing, not WP-09 golden acceptance.

### Allocation observation

Every generated recording is positive, serviced fully, and committed. Therefore every
chunk reserved for that edit is forced to materialize as one or more chunk-region
`dev_write` callbacks before commit. The verifier treats the unique chunk ids touched
by those callbacks as the externally observable allocation destinations for this
campaign.

This avoids trusting an implementation-internal allocation trace. The verifier
requires:
- every chunk write/allocation destination >= `a_high_water`;
- the first chunk destination equals the independently derived pre-action
  `free_next`.

## Generated reset action

Call `tape_reset_side_b` on the mounted Side-B-capable cartridge and capture:
- actual result;
- complete write-event trace;
- monotonic elapsed nanoseconds around the API call only;
- timeout status;
- raw post-unmount/remount B0/B1 metadata;
- public post-remount total frames.

The verifier requires:
- `TAPE_OK`;
- elapsed < 1,000,000,000 ns;
- no chunk-region write at all;
- live B entries exactly equal the unchanged Side-A index in the fuzz fixture.

The last requirement demonstrates that below-`a_high_water` Side-B references are a
legal result of reset and are distinct from allocation/write destinations.

## Post-remount allocation probe

After **every** random edit or reset has committed and remounted, perform:

1. derive nothing internally; merely keep the engine mounted on B;
2. `tape_seek` to the current end;
3. `tape_arm(TAPE_REC_OVERWRITE)`;
4. `tape_feed` exactly one zero PCM frame;
5. service until frames owed clear while recording every write callback;
6. `tape_abort` **before any index commit**;
7. unmount/remount before continuing.

Return the exact call results and write events.

The verifier independently derives expected `free_next` from the raw live-B index
that existed immediately before this probe and requires the first chunk-region write
to land on that exact chunk. It also requires the destination to be >=
`a_high_water`.

Because the probe never commits, its chunk write must disappear from allocator state
on the next remount; the next action's raw pre-snapshot must equal the previous
post-action committed snapshot.

This is the behavioral proof of invariant 12. No private/internal `free_next` value
is trusted.

## Deterministic reset stress case (< 1 s)

The verifier-owned reset-stress fixture contains:
- `a_high_water = 1`;
- a valid Side-A index with the maximum 4096 entries;
- all 4096 entries are one-frame, mutually disjoint physical intervals inside chunk 0.

This makes reset copy the maximum permitted entry array while moving **zero audio
chunks**.

The adapter runs one isolated `tape_reset_side_b` under a hard one-second watchdog.
Measure the API call itself with `CLOCK_MONOTONIC` and return:
- `elapsed_ns`;
- `timed_out`;
- all write events;
- raw post-remount B slots;
- timing environment:
  - clock name;
  - timer resolution in ns;
  - platform;
  - kernel;
  - CPU model.

A timeout/hang/process death is failure. The verifier requires elapsed < 1 s, no
chunk-region writes, and a live B index with all 4096 Side-A entries.

CI scheduling noise can cause a false failure; it cannot be converted into a pass.
Any rerun must be a new retained product run with its own provenance.

## Required response shape

Each sequence response is one JSON line with:

- `format = WP07-COW-RESULT-1`;
- exact sequence index/seed;
- `normal_exit=true`;
- `event_overflow=false`;
- exact initial B0/B1 raw snapshots;
- one action observation per generated action, in order.

Each action includes exact pre/post B slot snapshots, raw write events, operation
results, and a post-remount allocation-probe object. Edit observations also echo the
mode/selector/frame count/service budget and the resolved seek frame. Reset
observations include elapsed timing.

The reset-stress response uses `format = WP07-RESET-STRESS-1`.

Process death, timeout, malformed JSON, EOF, result-count mismatch, sequence
identity mismatch, media-continuity mismatch, or event overflow fails closed. The
runner retains the exact failing plan and observation rather than a 10,000-sequence
raw log.

## Evidence retention

Software retains:
- exact product commit/tree;
- verifier publication/tree;
- adapter source/binary hashes;
- build command/toolchain identity;
- complete adapter source;
- `summary.json`;
- empty/nonempty adapter stderr;
- any `failure-reproducer.json`;
- reset timing environment.

A green Software run is evidence only. Independent Verification must disposition the
exact binding and artifact before WP-07 acceptance.
