## Explicit deliberate-mutation route

The eight original patch paths/hashes are declared. `--mutation PATCH-STEM` is
allowed only for a declared patch. The checker reconstructs its expected engine tree
by applying the byte-exact patch to the pinned audited engine in a temporary Git index.
It checks that against the **actual committed mutant engine tree**. It retains the
unmutated epoch only as comparison identity; it never relabels mutant provenance.
Fetch the audited commit object if a shallow replacement checkout does not contain it.
Ordinary mode rejects mutant trees. Dirty worktrees and unsupported profiles fail closed.

Run the full unchanged behavioral campaign on a green unmutated baseline, then the
benign comment (behavior, raw and selection must all pass), then all seven mutations.
Mutation raw mismatch is diagnostic only: a causal catch must be an actual unchanged
behavior-oracle assertion, with successful selection and build. A provenance failure,
already-red baseline, raw-only mismatch or build failure is not a behavior catch.

`mutation-census --report REPORT.json` enforces the summary shape below, but does
not manufacture proof from JSON. Keep actual patch, build, execution, oracle assertion
and selection logs for independent final audit. Every mutation row must have a distinct
recorded execution with its real identities. Software must run the actual campaign;
this publication only validates the route and its rejection controls.

Report fields: `baseline_behavior_pass`, `baseline_raw_pass`,
`baseline_selection_pass`, `benign_behavior_pass`, `benign_raw_pass`,
`benign_selection_pass` (all true), and `mutations` (exactly seven rows). Each row:
`mutation` (declared stem), `selection_pass`, `build_pass` (true),
`failure_kind` (`behavior`), nonempty `oracle` and causal `assertion`,
`actual_commit`, `actual_engine` (40-character lowercase Git identities; mutant
engine differs from unmutated engine). Raw/provenance catches cannot satisfy this gate.
