# WP-09 R44 adapter contract

Build a separate Product adapter from issued Product main `788cb765493096a076603e5ad4ac6e2dea47a7a9` / engine tree `054d27ab6e3e72f61118ff7d99e19e48741d05b2`. Do not import this oracle into the adapter. The deterministic plan is `oracle.edits()` with seed `0x9E3779B9` and plan SHA-256 printed by self-test. Start from a formatted Side B writable device with enough sparse-file capacity for at least 10,000 fresh chunk allocations; initialize an empty timeline. For each edit, seek to `at`, arm `mode`, feed the exact interleaved stereo `frames`, service until owed frames are clear, then commit synchronously. Record all public results and callback events including block LBA and monotonically increasing per-edit ordinal. No private engine field may be used as an oracle.

Emit unabridged JSONL, one `wp09-r44-v1` object for every edit ID 1…10000 with `id`, `mode`, `at`, `input_sha256` over little-endian stereo PCM, `accepted`, `calls` (`seek`, `arm`, `feed`, `service`, `commit` results), and `events` (`step`, `op`, `lba` for reads/writes, `ordinal`, callback return). At every 400th edit include `checkpoint`: `id`, `after_remount` (true at 800, 1600, …; unmount/remount *before* observing), `render_pcm` (hex bytes of the entire logical Side B timeline at 1× from frame zero after service), `render_block_events` (only callbacks from `tape_render`), `pcm_sha256`, `raw_superblock` (512-byte selected candidate as hex), `raw_slots` (B0 and B1, each with the raw 512-byte header and exactly `entry_count × 12` entry bytes as hex; invalid headers carry zero entry bytes), `public_info` (actual `tape_get_info` `total_frames`, `entry_count`, `total_chunks`, `free_chunks`), and `mount_events` (raw engine callback events from the checkpoint remount, empty for non-remount checkpoints). At remount record both B-slot header reads. The oracle selects the higher valid raw B sequence and compares public timeline fields plus rendered PCM. It derives `free_next` from the selected raw B runs and superblock high-water per TapeFS §7; `free_chunks` must equal `total_chunks − free_next` after remount. Between remounts the in-memory bump pointer may be higher after overwrite, so `free_chunks` must be no greater than that raw-derived bound. Neither `free_next` nor selected-slot labels are public API fields or accepted as adapter assertions. Raw bytes are read directly from the file, outside engine callback accounting. Keep original JSONL and its SHA-256 with the source/build identity; `replay.py` writes a non-overwriting manifest binding evidence, oracle, adapter-source digest, Product SHA/tree and verdict. No restart of the history after a failing edit is allowed.

The generated compressed synthetic trace in `evidence/` is a parser/red-control reproducibility artifact, not Product evidence. To replay it, decompress to a new file and invoke `replay.py` with `--adapter-kind synthetic`. A Product adapter run must retain its own raw >1 MiB JSONL and committed SHA-256, not point to this synthetic artifact.

The full-acceptance branch is chosen deliberately. `engine-api` §7 says a short accept with `TAPE_ERR_CARTRIDGE_FULL` is the capacity edge and owes its accepted prefix; it does not define a positive `TAPE_OK` short-accept buffering rule. A 10,000-edit positive-short assertion would therefore be an invented requirement. Capacity short-accept remains for a separate, bounded capacity fixture if PM supplies a public buffering contract.
