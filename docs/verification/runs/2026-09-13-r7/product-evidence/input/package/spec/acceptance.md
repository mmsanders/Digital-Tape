| **WP-06** Block device, superblock, index commit | Format → mount → commit → unmount → mount round-trips on the file device. Every refusal path in `tapefs` §4.1 (**phase 0 plus phases 1–4**) and §5.1/§5.2/§5.3 has a test that exercises it, including the seven named below (WP-06a…WP-06g). `tape_commit` returns only after the final flush, writes **at most 97 blocks** and performs **exactly two flushes when it accepted any frames** — and **zero writes and zero flushes** for the no-op commit of `engine-api` §7.1, which WP-09 exercises (invariant 24) |
| **WP-06a** Effective writability *(V4-001)* | On a **writable** device carrying structurally valid **v1.1** media: mount succeeds, `tape_info.writable == false`, `version_minor == 1`. `arm`, `reset_b`, `promote` and `respool` return **`TAPE_ERR_READ_ONLY`**. `feed` and `commit` return **`TAPE_ERR_BUSY`** — the instance cannot reach the armed state, so `engine-api` §10's *Mounted, idle* row governs and `READ_ONLY` is not what a conforming engine returns there. The regression this guards is a one-power-loss, ordinary-use path that permanently disabled promote |
| **WP-06f** Both-side mount *(`tapefs` §4.2)* | A cartridge whose **Side A** index is unselectable fails the mount with that error **whichever side was requested**. **Both causes of degraded-B are exercised** *(V6-001)*: (a) neither B slot valid, and (b) **B0 and B1 both valid at equal `sequence` with different entry arrays**, which §5.3 refuses as `TAPE_ERR_INCONSISTENT`. In case (b), after `tape_reset_side_b` the suite must **unmount and remount** and assert the *new* B index is the live one — a recovery that writes B0 at a sequence below the surviving B1 returns success and changes nothing on the next mount, which is the defect this case exists to catch. A cartridge whose **Side B** index is unselectable mounts on **Side A** with `free_next == a_high_water`, and `tape_reset_side_b` from that mount recovers it — while a mount **requesting Side B** returns **that side's own §5.3 error** — `TAPE_ERR_NO_VALID_INDEX` in cause (a), **`TAPE_ERR_INCONSISTENT` in cause (b)** — and `tape_set_side(TAPE_SIDE_B)` on the Side-A mount returns `TAPE_ERR_NO_VALID_INDEX` in both. Without those two refusals the API reaches a mounted state with no live index for the mounted side. A Side-A mount of a cartridge with a recorded Side B derives `free_next` from **Side B's** live index, and a `respool`/`promote` issued from that Side-A mount allocates above it — asserted by the simulator, since the failure mode is allocating over Side B's live chunks. **In degraded-B, `tape_promote` and `tape_respool` must each return `TAPE_ERR_NO_VALID_INDEX` with zero `dev_write` calls** *(V5-004)*; `tape_reset_side_b` must succeed and leave the mount non-degraded, with `tape_info.side_b_valid` false before and true after — **and `tape_set_side(TAPE_SIDE_B)` must then succeed**, since the refusal is keyed to current state, not to mount-time. `tape_set_side(TAPE_SIDE_A)` must succeed *while* degraded. **All fifteen cells of the degraded-B row are exercised.** In degraded-B, `tape_reset_side_b`'s destination is **B0** written directly (`tapefs` §9.2), because neither slot is live and "inactive" would be undefined. A cartridge that is **both** degraded-B and `promote_stage == 1` must **mount** — degraded-B is decided before the stage oracle — and be recoverable by `tape_reset_side_b`, whose stage-clearing write resolves the stage. That cartridge is reachable and under DRAFT-6's first cut it was permanently unmountable, taking all of Side A with it. The failure this guards is an engine that silently treats an absent B as empty — promote of an empty B erases Side A |

The old bare-`uint64_t` signature had no error channel at all, so an implementation had to invent a sentinel |

One accepted case per RESUME row, and at least three crafted unmatched cases. Then the general assertion: across every refusal in WP-06a–06f, `tape_mount` performs **zero writes on every failing path** (invariant 26). Separately, a stage-1 cartridge matching no row must not be *repairable into silence*: assert that `tape_arm` on it is never reached, because the mount already refused |
| **WP-07** Allocator, copy-on-write Side B | `tape_reset_side_b` completes in < 1 s and **moves no chunk**. Fuzzing over 10 000 random edit sequences never produces a Side B **allocation or write destination** below `a_high_water`. Side B *references* below the mark are correct and must not be flagged — the oracle identifies ownership by allocation, not by chunk id. `free_next` after remount equals invariant 12's derived value. **Every committed index satisfies interval disjointness** — a trim that leaves two entries claiming one physical frame is a defect |
| **WP-08** Playback, seek, scrub | 1.0× playback bit-exact against `tests/golden/`. Every rate in the ramp table bit-exact. **`tape_seek(N)` followed by `tape_render` emits frame `N` as its first output**, asserted at every run boundary and at ±1 frame around it *(V4-010)*. The `engine-api` §6.2/§6.3/§8 algorithms are the only implementation of the arithmetic. Required boundary cases: **one-frame timeline at `rate_q16_16 = INT32_MAX`** must clamp at `max_pos`, not overshoot *(V4-009)*; zero-frame timeline; `rate_q16_16 = 0`; reverse from 0 emits frame 0 once then stops; reverse at the most negative rate does not wrap position. **Reverse-from-end is a multi-frame golden, not a first-sample assertion** *(V5-005)*: from `position == max_pos` at exactly −1.0×, a non-constant timeline must emit its frames in exact reverse order, grid-aligned — for `[0, 1000, 2000]`, the output is `2000, 1000, 0`, not `2000, 1999, 999`. **`tape_set_side` transition** *(V5-013, V6-005)*, in two reachable parts. **(i) From Playing**, which `engine-api` §10 now permits: render Side A forward at 1.0× to the end so `at_end` is genuinely set, then `tape_set_side(B)` onto a shorter non-empty Side B. Assert position 0, **both flags cleared**, `warm_start_used` false, the **rate retained**, and that the first `tape_render` before any `tape_service` returns `TAPE_ERR_UNDERRUN` with `*rendered == 0`. **(ii) From idle**, the same assertions with the rate set non-zero *after* the switch. DRAFT-6 demanded BUSY from *every* call, contradicting its own four exemptions, and its termination rule read literally ended the operation on that BUSY |

## Stream 2 — Verification

### WP-10 — Crash injection

Power loss injected at **every** write boundary, and torn writes at every block write, across a scripted session covering format, load, play, overwrite, overdub, splice, commit, reset B, re-spool (both passes), promote (all boundaries in `tapefs` §9.3.4), **the stage-clearing superblock write that `arm`/`reset_b`/`respool` perform on stage-1 media** (`tapefs` §8), and duplicate. **Exhaustive, not sampled** — the injection-point count is reported.

**Promote's three superblock writes are four injection points each, not one** *(M-5 of the DRAFT-7 audit, restated under §4.6)*: step 4, step 5's decline and step 9 are all *partner, flush, candidate, flush*, and the new partner wins §4.1 selection **as soon as it is durable**. So each of `tapefs` §9.3.4's superblock-adjacent rows admits the state before **and** after that write; enumerate both.

**Two-interruption closure *(V7-001)*.** Seed each superblock-writing operation — promote steps 4 / 5-decline / 9, and §8 stage clearing — from every permitted one-copy or newer-partner recovery state that a first injection is allowed to leave, then inject a second torn write or power loss on the next partner write. After the second interruption the mounted cartridge must still be one of that operation's permitted outcomes; specifically it must never present a stale lower-generation superblock as the only structurally valid copy while live Side A indices fail `last < a_high_water`. The one-fault-from-clean-fixture enumeration cannot see this path.

**Every boundary runs in both durability modes** *(V5-010)*: flush-required (a completed write is durable only after its flush returns) and **write-through** (a completed write is durable immediately). `tapefs` §8.1 makes both legal, and a boundary lying between a write and its flush therefore has **two** permitted outcomes, not one. A runner that models only the first will reject safe cartridges; a runner that models only the second will miss the ones the ordering protocol exists to protect. The mode is reported alongside the injection-point count.

**The shared sequence base** *(V6-003)*. Craft a cartridge with **live A at `sequence = 10` and live B at `sequence = 500`** — reachable by editing Side B repeatedly after a format — and assert that the next commit from **either** side writes **501**, not 11: `cartridge_sequence` is the maximum over every **structurally valid** slot (`tapefs` §5.5), including slots that lost selection. A promote from the Side-A mount on that cartridge must complete; under a side-local reading it produces a stage-1 state the oracle rejects.

**Branch-exact headroom** *(V6-002, V7-002)*. Three cases the DRAFT-6 table got wrong, each asserted to take its *specified* result rather than `TAPE_ERR_SEQUENCE_EXHAUSTED`: **empty re-spool at `cartridge_sequence = 0xFFFFFFFD`** → `TAPE_OK`, zero writes; **RESUME-at-step-5 that will decline** (`S < len`) at `0xFFFFFFFC` → completes, committing no index; **FRESH promote that will decline** at `0xFFFFFFFB` → completes phase 1. Then the converse: each branch one short of *its own* requirement must refuse with zero writes. **Zero-needed at the reserved values:** empty re-spool and NOTHING-TO-DO promote at `sequence` and at `sb_generation` equal to `0xFFFFFFFE` and `0xFFFFFFFF` each return their specified success or classification with zero writes — those counters are not consulted when `needed == 0`.

**Counter boundaries** *(V5-015)*. For **each branch** of each operation, craft media at `sequence` or `sb_generation` one short of the headroom `tapefs` §4.5 requires for that branch, and assert `TAPE_ERR_SEQUENCE_EXHAUSTED` with **zero writes** — in particular `tape_promote` at `sequence == 0xFFFFFFFC`, which under DRAFT-5 committed phase-1's A index and then had to refuse phase-1's B index, leaving a cartridge whose only specified completion path could never run. Include a reusable raw destination at `sb_generation >= 0xFFFFFFFD` for `tape_format` and `tape_dup`, and assert the zeroing boundary fallback rather than a wrapped generation. **Two shapes of that destination are mandatory** *(V6-008)*: both copies valid, and **the mirror as the only structurally valid copy** — a recoverable cartridge these raw operations accept because they do not mount first. **A `sb_generation = 0` destination is a mandatory shape** — crafted or foreign media with a CRC-correct superblock at generation 0, which these raw operations accept because they validate only magic and CRC. **Two more raw-admission shapes *(V7-003, V8C-003)*:** a destination whose only structurally valid copy has `version_major = 2` — step 1 writes the v1 WIP template and remount is `TAPE_ERR_INCOMPLETE`, never `TAPE_ERR_VERSION`; and both copies valid at equal `sb_generation` with different CRC-correct contents — after refusal preconditions pass, **when headroom exists** step 1 writes the same v1 WIP template with the healthy-pair tie-break (mirror partner, primary candidate). A destination that is *both* equal-generation-divergent *and* fails geometry or capacity must return that refusal with **zero writes and zero destination superblock reads**. Assert step 1 is **still performed** on the ordinary path (the `WRITE_IN_PROGRESS` barrier is never skipped) and writes generation **2**, so that "higher generation wins" holds at the final two writes and no injection point yields a cartridge that mounts under the *destination's previous* UUID. **Step 1's ordinary write order is also asserted** — partner first, candidate last, mirror first on a byte-identical healthy pair *and* on an equal-generation-divergent pair — with a torn first write leaving the candidate intact. Assert the generation-exhausted fallback zeroes the **non-selectable copy first** on every shape that has a §4.1 candidate, so that a power cut between the two zero writes leaves the old cartridge still selectable rather than `TAPE_ERR_BAD_MAGIC` on reusable media. **Mandatory exhaustion × equal-generation-divergent shape *(V8R2-001)*:** both copies structurally valid, byte-divergent, `sb_generation = 0xFFFFFFFD`. After refusal preconditions pass, step 1 takes the zeroing fallback (mirror first). A power cut after the first durable zero leaves **the mount result of the surviving primary**, not `TAPE_ERR_INCOMPLETE` and not a guaranteed "old cartridge unchanged." Both zeros durable is `TAPE_ERR_BAD_MAGIC`.

**Equal-generation-divergent crash oracle *(V8C-003, V8R2-001)*.** Split on headroom. **With headroom:** after every injection the remount result is exactly one of: `TAPE_ERR_INCONSISTENT` (no template write durable, both copies still valid and still divergent); the **mount result of the surviving unwritten copy** if the first template write tore; `TAPE_ERR_INCOMPLETE` once any template write is durable; or the completed new cartridge. A durable first *template* write is never "the old primary, as-is." **Without headroom** (`sb_generation ≥ 0xFFFFFFFD`): `TAPE_ERR_INCONSISTENT` if the first zero has not landed; the **mount result of the surviving primary** once the first zero is durable or tore; `TAPE_ERR_BAD_MAGIC` once both copies are gone; or the completed new cartridge. That first-durable-zero state is not `TAPE_ERR_INCOMPLETE` and is not "the old cartridge, unchanged."

**The final superblock step is two injection points, not one** *(V6-007)*: the mirror write/flush and the primary write/flush, each in both durability modes, **plus a torn primary**. At the final primary write the permitted set is `TAPE_ERR_INCOMPLETE` where the old `WRITE_IN_PROGRESS` primary is still durable, **and the completed cartridge** where the new primary is durable or the primary tore — a torn primary fails CRC and §4.1 selects the already-valid mirror. `tape_format` had no row for "inside step 5" at all.

**Universal assertions, after every injection:**

- No allocated chunk is unreachable from the live index **beyond what `tapefs` §7 permits**. Precisely: `free_next` equals `max(a_high_water, max over live-B entries of last + 1)`. **Chunks superseded by an overwrite are expected to be unreachable and must not be reported** — they are the format's only sanctioned leak and re-spool reclaims them. *(DRAFT-2's blanket reachability assertion contradicted the allocator and would have failed every ordinary overwrite; V3-014.)*
- The live index of each mountable side passes `tapefs` §5.2 in full, **including interval disjointness**.
- **`sequence` advanced and `sb_generation` did not**, for every ordinary index-only operation — recording, reset-B, re-spool without stage clearing (invariant 7, V6-004). Asserting both counters advance would fail every ordinary recording. **And the positive half**: `sb_generation` **did** advance on every ordinary superblock update of an existing cartridge — promote's steps 4, 5-decline and 9, stage clearing, and format's and duplicate's **step 1** — and **repair advanced neither** — invalid partner *and* stale lower-generation partner *(V7-001)* — asserted by remounting each shape on a writable device and comparing both counters before and after. **Identity boundary *(V8C-002)*:** a completed format or duplicate ends at `sb_generation = 1` with A0/B0 at `sequence` 1 and 2; do not assert that those identity-assignment commits increased either counter.
- **No two structurally valid slots on one cartridge share a `sequence`** — the running-counter rule of `tapefs` §5.5. Assert it after **every** injection in a FRESH promote, which commits four indices: DRAFT-7's first cut reused `cartridge_sequence + 1` and `+ 2` for steps 7 and 8, putting two equal-sequence valid slots on Side A and making the cartridge unmountable and unrecoverable.
- Referenced audio is intact for whatever generation is selected.
- **`promote_stage` on media is 1 only in the states invariant 25 permits**, and any **non-degraded-B** mount with `promote_stage == 1` matches exactly one row of §9.3.3 — a non-degraded-B mount that matches none must return `TAPE_ERR_INCONSISTENT`, and the suite must contain a deliberately corrupted case that does. **A degraded-B mount is exempt**: `tapefs` §4.2 evaluates degraded-B first and skips the oracle, because every row constrains a live Side B index. That cartridge mounts, and WP-06f requires it to.

**Per-operation allowed-state sets.** DRAFT-2 required "remount succeeds, Side A byte-identical to session start" for every injection, which contradicts what duplicate, format and promote are specified to do (V3-013). Each operation now has its own oracle:

| Operation | Permitted outcomes after any injection |
|---|---|
| Play, seek, scrub | No change to either side |
| Overwrite, overdub, splice, commit | Side A unchanged (referenced frames). Side B is **exactly** the pre-operation or post-operation generation, never between |
| Reset B | Side A unchanged. Side B is the pre- or post-reset generation. **In degraded-B case (b)** — both slots valid at equal `sequence` — a crash after B0's entry array lands but before its block 0 leaves **B1** as the sole valid slot and therefore live: a **third** permitted outcome, and the one the oracle must not treat as corruption |
| Re-spool | Side A unchanged. Side B renders bit-identically to before, in either the pre-pass or post-pass layout. **Never a layout referencing overwritten chunks** |
| **Promote** | Side A and Side B are each one of the **eleven** enumerated rows in `tapefs` §9.3.4 — including the mixed pair from a crash between steps 3 and 4, **the A-low/B-high pair from a crash between steps 7 and 8, and the both-low/old-high-water state from a crash between 8 and 9** *(V4-003)*. All referenced audio intact in whichever generation is selected. **Side A is not required to be byte-identical to session start; a completed promote changes it by design.** Empty Side B returns `TAPE_ERR_INVALID_ARG` having written nothing |
| **Promote, `S == 0`** *(the first-use path)* | Format, record onto the empty Side B, promote. Adopt-in-place gives `S = 0`, so **every** injection between steps 4 and 6 must match **exactly one** row of §9.3.3 — row 1 — and resume to the completed layout via step 5's decline. Invariant 25's "exactly one row" is asserted here specifically, because this is where DRAFT-5's first cut had two rows matching the same media |
| **Promote, stored position** | **Every `tape_promote` returning `TAPE_OK` clears the stored `(uuid, A)` and `(uuid, B)` positions** — asserted on the full path, on the step-5 decline, on a resume entering at step 8 and at step 9, and on the NOTHING TO DO classification — on the **terminal** call only (`*more_work == false`), so an incremental promote does not rewrite the position table on every continuation. The last of those is the one that matters most: a crash between the final superblock write and the position clear leaves media complete but positions stale, and the re-run that has to clean it up is exactly the call that commits nothing |
| **Promote, re-run** | From **every** row of §9.3.4, a repeated `tape_promote` must reach the completed state **without performing a second chunk copy where the table says none is needed**, asserted by counting chunk-region writes. Two cases are mandatory: **(a) exact tail capacity** — a cartridge with exactly `len` free chunks above the original `free_next`, crashed between phase-1 steps 3 and 4, must complete via adopt-in-place and must **not** return `TAPE_ERR_CARTRIDGE_FULL` *(V4-004)*; **(b) repeated crashes at that same boundary** must not consume successive staging runs — free-chunk count is asserted non-decreasing across the retries |
| **Duplicate, empty source** *(V5-002, blocker)* | A **freshly formatted source** — valid, zero entries, `total_frames == 0` — copied onto (a) blank media and (b) a **reusable destination holding a good cartridge**. Required outcome: a valid empty cartridge with `a_high_water == 0`, A0/B0 as **zero-entry** headers at `sequence` 1 and 2, a fresh UUID, and **it must mount on both sides**. Run every crash boundary of this copy. The regression is severe and was reachable by a child copying a blank tape: DRAFT-5 wrote a `frame_count == 0` entry, which §5.2 forbids, then committed `state = VALID` — `tape_dup` returned `TAPE_OK` having destroyed the destination and produced a cartridge with no selectable Side A. Assert alongside it the other three empty cases (`promote` → `INVALID_ARG`, `respool` → `TAPE_OK`, zero-frame `commit` → no-op) so the family is checked as a family |
| **Duplicate, destination shape** *(`tapefs` §9.5)* | A completed copy has `a_high_water == ⌈src_A.total_frames / CHUNK_FRAMES⌉`, Side A compacted to `[0, a_high_water)`, `sb_generation == 1`, A0 at `side = 0`/`sequence = 1` and B0 at `side = 1`/`sequence = 2`, and **`label` byte-identical to the source superblock `label`** *(V7-004)*. **The destination must mount on Side B as well as Side A** — a B0 written with `side = 0` fails §5.2 and would leave the copy with no usable sandbox. **Three mandatory regressions:** (i) the copy **mounts** — a destination whose `a_high_water` was left stale or zero fails §5.2's Side A bound and is unusable; (ii) a **layout-preserving** copy is rejected by construction — copy a fragmented C-90 source onto a C-60 destination that passes the capacity precondition and assert no chunk id ≥ destination `total_chunks` is ever addressed; (iii) **reusable destination** — pre-load the destination with a valid A0 at `sequence = 500` for a *different* cartridge, run `tape_dup`, and assert the mounted audio is the source's, not the old cartridge's. That last one is silent data substitution, not a crash |
| Duplicate | **Source unchanged, always** — absolute. Destination remount is one of: the pre-copy cartridge; `TAPE_ERR_INCONSISTENT` (equal-generation-divergent, no first write durable); the mount result of a single surviving structurally valid copy after a torn first template write **or after a durable/torn first zero of the generation-exhausted fallback** *(V8R2-001)*; `TAPE_ERR_INCOMPLETE` once a template write is durable; `TAPE_ERR_BAD_MAGIC` if it was blank, or after the generation-exhausted fallback zeroed both copies, and crashed before the final superblock; or the completed copy with its fresh UUID, `sb_generation == 1`, and a Side B mirroring its new Side A *(V8C-003)*. **Each of the four *refusal* preconditions — aliasing, read-only destination, geometry, capacity — writes nothing at all** (invariant 18), geometry including **zero callbacks of any kind** on `block_count ∈ {0, 1, LBA_CHUNK_BASE}` *(V8R2-002)*, and a destination failing more than one must return the error the `tapefs` §9.5 order specifies *(V4-006)*. **The re-run path must be exercised**: after an interrupted copy, calling `tape_dup` again on the same destination *device* must complete it |
| Format, reusable media | The old cartridge unchanged **when a §4.1 candidate exists**; `TAPE_ERR_INCONSISTENT` or the surviving-copy mount result on the equal-generation-divergent first-write boundary *(V8C-003)*; the surviving-primary mount result after a durable or torn first zero of the generation-exhausted equal-generation-divergent fallback *(V8R2-001)*; `TAPE_ERR_INCOMPLETE` once a template write is durable; `TAPE_ERR_BAD_MAGIC` after both fallback zeros and before the final superblock; or the new empty cartridge. **A raw device failing `GEOMETRY_OK` is refused with `TAPE_ERR_GEOMETRY`, zero writes and zero callbacks of any kind on `block_count ∈ {0, 1, LBA_CHUNK_BASE}`, before any block is destroyed or read as a superblock** *(V4-006, V8C-001, V8R2-002)* |
| Format, blank media | The above, **or `TAPE_ERR_BAD_MAGIC`** — until step 4's mirror write is durable, no valid superblock has ever existed and remount cannot succeed. This is the single permitted "does not mount" case in the whole suite. **Once that mirror is durable, the permitted outcome is the new empty cartridge** — one structurally valid superblock, both empty indices durable. On the harness's writable device **phase 4** repairs the primary and **`needs_repair` must be false**; the `needs_repair == true` form is asserted on a read-only device instead *(V4-014)*. In write-through mode the mirror becomes durable at the write rather than at the flush, so **both outcomes are permitted at that single injection point** *(V5-010)* |

### WP-11 — Golden suite and runner

One command runs everything. Comparison byte-exact, **no tolerance** (ADR-016). A failure emits an audible-difference WAV plus first differing frame, channel, both values, delta, count and peak. Fixtures are generated once, listened to by a human, and committed; regeneration requires logged PM approval.

**Goldens may not be frozen until three things are true**, all of which DRAFT-5 supplies and none of which DRAFT-4 did: the render phase convention (`engine-api` §6.3), the portable negative-interpolation rule (§8), and the checked warm-range arithmetic (§5).

**Portability gate *(V4-013, V5-006, V5-012)*.** Full-domain equivalence is established by the **proof in `engine-api` §8**, not by execution — the literal domain is ~5.6 × 10¹⁴ pairs and no gate can run it, which is what DRAFT-5's "exhaustive-by-construction sweep" was pretending otherwise.

The **executable** gate is a finite differential test of the implementation against `⌊d / 2³²⌋` computed independently:

- **all 131 071 values of `b − a`** in `[−65535, 65535]`, crossed with the twelve-value boundary set `f ∈ {0, 1, 2, 0x40000000, 0x7FFFFFFE, 0x7FFFFFFF, 0x80000000, 0x80000001, 0xC0000000, 0xFFFFFFFD, 0xFFFFFFFE, 0xFFFFFFFF}` — 1 572 852 pairs, seconds to run;
- **plus 10⁷ pairs from a seeded PRNG**, the seed committed;
- **plus every `(b, a)` at the int16 extremes**, specifically `b = 32767, a = −32768` and its negation — the pair that overflows a 16-bit `int` if either operand is cast late.

Green on **at least two toolchains, one of them the embedded target, and at least one configuration in which integer-promotion width is visible** (`-fshort-enums`-style narrow-`int` build, a 16-bit target, or a static assertion on `INT_MAX` plus a compile-time check that the operands are cast before subtraction). A single-toolchain green is not evidence of portability, and DRAFT-5's own "portable" formulation still contained a pre-cast overflow that only such a configuration surfaces.

**Mutation testing before each phase gate.** Seven mutations, each caught:

1. Off-by-one in a chunk boundary calculation.
2. Index commit written *before* the chunks are flushed.
3. `sequence` not incremented on commit.
4. CRC computed over the wrong byte range.
5. A Side B **allocation** permitted one chunk below `a_high_water` *(the allocation, not a reference — see WP-07)*.
6. Saturating clamp replaced with a plain cast, so overdub wraps.
7. **Warm-start buffer accepted for the wrong `(uuid, side, frame range)`.** Fixtures must include `start_frame` near `UINT32_MAX` with non-zero `valid_frames`, `valid_frames == 0`, and `data_bytes` one byte short of `valid_frames × 4` *(V4-011)* — **plus the two pointer cases *(V5-007)*: `warm == NULL` (the ordinary cold mount, which must read no field of the descriptor) and a fully valid descriptor with `data == NULL`.** Both must fall back to a cold mount with `warm_start_used == false`, and the simulator must confirm no load from address zero.

Any mutation the suite does not catch is a coverage gap and a finding of equal weight to an engine bug.

## Firmware criteria referenced by the specs

| Behaviour | Criterion |
|---|---|
| **Commit latency** *(V4-008)* | Worst-case wall time of a synchronous `tape_commit` at `TAPE_MAX_ENTRIES`, measured on the bench build against the slowest candidate card: **< 200 ms**, and in every case less than the play ring's depth (~372 ms). This number is what makes `engine-api` §7.1's "bounded" a fact rather than an assumption. A card that misses it is a card-selection finding, not a licence to make commit incremental |
| **Instant-on, warm** | Wake from sleep with a mounted cartridge to first rendered non-silent frame: **< 100 ms**, measured on the bench build with a logic analyser on I²S |
| **Warm-start validity** | The retained ring is passed as a `tape_warm_start` descriptor with correct `uuid`, `side`, `start_frame`, `valid_frames` and `data_bytes`. A deliberately mismatched descriptor must produce `warm_start_used = false` and a correct, silent-free mount — **not** audio from the wrong cartridge |
| **Instant-on, cold** | Card init begins within 20 ms of the cartridge-detect switch closing. Play pressed 1 s after insert produces audio within 100 ms of the press |
| **Resume position** | Checkpoint to device flash every 10 s of playback and on every transport state change. After abrupt removal, resume lands in `[T − 12 s, T − 2 s]` where **T is the true position at the moment of removal** — not the checkpoint. Measuring against the checkpoint would admit a 10 s error the specified algorithm cannot produce and would fail to catch a cadence regression. Table holds 64 `(uuid, side)` entries, LRU. Promote clears both entries for that UUID; reset B clears `(uuid, B)` |
| **Scrub ramp** | Rate schedule driven into `tape_set_rate`: 4.0× at t=0, linear to 12.0× at t=1.5 s, hold. Reverse mirrors with negative rates. Scrub goldens drive this exact table |
| **Record light** | Colour from `tape_status().entries_free` as a fraction of `TAPE_MAX_ENTRIES`: **green** ≥ 25 % free, **yellow** < 25 %, **red** at 0 — and at 0 the record button does not hold. Off while not armed |
| **End of tape** | `at_end` releases the play button within 50 ms |
| **Cartridge full mid-record** | On `TAPE_ERR_CARTRIDGE_FULL`, firmware stops the transport, releases the buttons, and commits. The recording up to that point is present on the next mount |
| **Output cap** | Codec output limited in the volume register to the level producing 85 dB SPL on the specified reference headphones, re-asserted every boot, unreachable from any user control. SPL meter and coupler, **witnessed by Michael** |
| **Copy progress** | LED row position reflects `blocks_done / blocks_total` from the progress callback; never a timer |

## Media atomicity — the format's one physical assumption

`tapefs` §8 and §13 rest on a 512-byte SD block write being atomic under power loss. It is true of essentially every card in practice and is not universally guaranteed, and DRAFT-4's first cut cited a work package (WP-19) that does not exist in this document — so the format's single load-bearing physical assumption had no acceptance criterion at all.

**Criterion.** On each candidate card SKU, with the card powered from a switched supply: write a known 512-byte pattern to a fixed block, cut power at randomised offsets inside the write window, then re-read. Across at least 1 000 cuts per SKU, every read must return **either** the previous content **or** the new content in full — never a mixture. A single torn block is a blocker finding and forces a format change, not a firmware workaround.

Run during **WP-05** card characterisation, on the same cards bought for the sustained-write measurement. Results recorded per SKU with revision, alongside the write-speed numbers.

> **WP-04, WP-05, WP-22 and WP-26 are hardware work packages and are defined in `claude/digital-tape-player-plan.md`, not here.** This document defines WP-06…WP-13 and WP-36 only. Saying so explicitly because DRAFT-4 cited a work package that existed nowhere, and a reader had no way to tell the difference between that and a cross-document reference.

## Hardware safety limits (PM-owned; measurements live in `spec/hw/`)

**Independent audit.** Every measurement in this table is **witnessed by Michael and independently audited by the Verification Lead** — method and raw data, not physical presence. The deliverable is therefore written to be audited by someone who was not in the room: **procedure; instrument, model and calibration date; ambient conditions; raw readings; the derivation from readings to the stated result; and the measurement uncertainty.** A result without a stated uncertainty is not auditable, and the thermal margins here are narrow enough that the uncertainty can decide pass or fail.

*(Issue #23, raised by the Hardware Lead: PM Decisions 008 §4 told three people this audit had been added to `acceptance.md`, and DRAFT-6 contained the string "audit" zero times. The rows said "witnessed by Michael" and nothing else. This is the second time this round that something I announced as done existed only in a communiqué.)*

**These state limits, not mechanisms.** DRAFT-1 named the charger's NTC input as the means of enforcing the charge window, which over-constrained a limit into an implementation no candidate part could meet. How a limit is met is the Hardware Lead's choice; *that* it is met, in hardware and not defeatable by firmware, is not.

| Limit | Value |
|---|---|
| **Charge window** | Charging suspended below 0 °C or above **45 °C** cell temperature. Enforced in hardware; firmware cannot override. Mechanism is the Hardware Lead's — a TS network designed so 45 °C maps to the charger's hot-suspend threshold, a part with a suitable threshold, or a series cutoff. **Note:** a BQ25896's native hot *suspend* is T5 ≈ 60 °C; T3 ≈ 45 °C only drops charge voltage 200 mV ([TI datasheet](https://www.ti.com/lit/ds/symlink/bq25896.pdf)). Verified by sweeping cell temperature across both thresholds |
| **Solenoid — single pulse** | Bounded in hardware to the shortest duration that reliably releases the latch, plus stated margin. **The number comes from WP-04/WP-22 measurement, not from this document.** Verified by holding the gate high and measuring coil current |
| **Solenoid — sustained power** | **Average coil power ≤ 0.25 W over any rolling 10 s window**, enforced in hardware, not defeatable by firmware. Stated as power because power is what damages a coil. The limit must sit above the fastest legitimate use — a child alternating stop and play about twice a second — and below the coil's continuous rating; if those do not leave a gap the answer is a shorter pulse or a lower-power coil, not a looser limit. Verified by driving the gate at 100 Hz continuously: average coil power must fall to and stay at or below the limit within 2 s. Component values and worst-case tolerance are part of the deliverable before WP-26; a PPTC is a third-layer backstop and may not be the element establishing this bound |
| **Worst-case thermal** | Charge at full rate + copy + all LEDs for one hour: no external surface above ambient + 15 K; cell surface below 45 °C. **Junction temperatures of the charger, regulator and MCU reported individually**, not inferred from a lumped enclosure model — a 30 s copy is a transient the lumped model does not resolve. Witnessed by Michael |
| **Deep-discharge latch** | Hardware load switch disconnects the cell below ~3.2 V, released by charger insertion. Must not add perceptible latency to wake-from-sleep; if it does, escalate rather than trading against instant-on |
