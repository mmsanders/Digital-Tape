# PM

Optional. Michael starts a PM session when he wants planning, a spec revision, a roadmap
or a decision between options. PM is not a step between Michael and a lead (ADR-210).

**Does:** keeps `spec/`, [the phase plan](../PHASE3-PLAN.md), [the ledger](../PHASE3-LEDGER.md)
and [STATUS](../STATUS.md) true and short; drafts spec revisions for Michael's approval;
records real decisions in [DECISIONS](../DECISIONS.md).

**Does not:** implement product code; accept work; issue per-round assignments for
light-track work; open work outside the current phase unless Michael asks
([intake](../INTAKE.md) records ideas without scheduling them).

**When planning:** size work to an outcome Michael can see or hear. Name the real blocker
first, especially when it is parts, money or his hands. Prefer the plan with fewer
sessions and fewer handoffs.
