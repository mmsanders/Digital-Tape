**ADR-208 (6 Nov 2026) governs this package's method.** Card identity is brand, part number
and capacity from the card and package, plus a photo. The firmware logs the CID over native
SD when the bench runs; it is recorded when available and is not required. No reader is
bought for it. Michael's cards are recorded in
[evidence/cards](../evidence/cards/README.md) (7 Nov 2026). The reader must not be the measurement ceiling. A
parts order never authorizes board fabrication or cell charging.

## Criteria

| # | Criterion |
|---|---|
| A-1 | Michael-approved sample set and his existing reader in hand; brand/model, capacity and a photo per card, part number when known (otherwise explicitly unknown; CID optional) |
| A-2 | Per candidate SKU/revision, at least one sustained-write run on 80%-filled media: ≥1200 MB transfer, worst 64 MB window and raw per-window data. Unfilled repeat/unit/control runs are useful screening evidence but do not replace the filled run |
| A-3 | Evaluate against C-60 end-to-end copy requirement; no automatic return to the superseded 90-minute rule |
| A-4 | Establish the reader is not the bottleneck; similar top results at its ceiling invalidate a card-speed conclusion |
| A-5 | Approved Phase 3 bench parts support the firmware bench and the atomicity rig |
| A-6 | Every candidate card model: ≥1,000 qualifying cuts by the Teensy self-run test; zero torn/corrupt blocks or neighbour damage |

C-60 contains 635,040,000 PCM bytes per side. Payload alone requires 21.168 MB/s
over 30 seconds; bus/metadata/initialization and both source/destination work still
need end-to-end verification. A nominal 25 MB/s bus ceiling is not measured margin.
The existing tool reports against a 23.3 MB/s headroom bar; that threshold is
unchanged by this cleanup and is not end-to-end acceptance. The Teensy bench checks function; PC tests characterize media; production validates
the actual copy requirement. V30 is not an atomicity guarantee.

The 80% fill condition stands: low occupancy does not prove the card's flash layer avoids
garbage-collection stalls.

## Current atomicity method — ADR-208 / ADR-209

The Teensy self-run method replaces the external rail/timebase/U method. Firmware
writes a single block, observes protocol busy, switches card power with discharge,
re-powers and reads target plus four neighbours. Model identity is brand/model or
part number/capacity/photos, plus a labeled physical unit and run/plan/build linkage.
A missing retail part number is recorded unknown when packaging is unavailable;
never invent it. CID is optional diagnostic-only, including disagreement; no new
reader or fake CID. Preserve conflicting observations for review.

The new plan5/selfrun-r1 public declaration is PR673/c32f1a56, supplemented by
ADR-209. Hardware675 and V405 bind/implement it before any physical use. Old plan3/
plan4 and rig-r2 tests remain immutable. New-route logical checks: last busy sample
to cut <=5us (greater is a retained miss); observed off voltage <=200mV (greater is
a run problem), same build/plan/unit and exact serial→mapped-log/binary linkage.
Fixed1000 distinct qualifying cuts; every attempt and all damage remain audited.
Accepted full payload with validated observed completion <=cut and OLD is a
run-integrity FAIL (completed_before_old), not automatically TORN or a card defect.
NEW on that late completed write is a retained miss without qualifying credit.

SPI4MHz is the adopted Phase3 model-atomicity evidence route with explicit actual
bus/speed and one-unit-per-model residual risks; retain spi-characterisation scope.
A later complete independently checked run and Michael record can meet A-6 under
this method. It does not prove SD4 equivalence, production copy throughput, other
cards/modes or lifetime reliability. No native-mode rig or retired instruments are
required. No card/method/campaign is physically qualified by this document.

### Legacy procedure and CLI examples — historical routes only

The following exact SKU/revision/CID, external traces and uncertainty-U examples
describe legacy plan3/plan4/rig-r2. They are NOT prerequisites or executable
instructions for the new optional-CID selfrun-r1 route. Its CLI/binding is still
being implemented; do not fill a fake CID or use legacy PASS as new-route clearance.
The shared keep-every-result, strict1000 minimum and target/neighbour integrity
rules carry. The old method-specific predicates are retained as history below.

Commit the plan before the run. Bind every result to SKU, revision, CID, run id and
plan digest. Count distinct qualifying trials, not rows. Planned attempts and required
qualifying cuts are separate; use an auditable plan extension if misses consume the
surplus. The judge’s 1,000 minimum cannot be reduced through operator input.

Before every cut trial establish the exact old target pattern by a completed write
and verified read. Preserve separate baselines for all four neighbours (-2, -1, +1,
+2). Missing/malformed neighbour data invalidates the run; never assume a prior
interrupted trial completed.

A cut qualifies only with evidence of all four steps: full single-block payload
transferred; accepted data-response token; observed entry into protocol busy; busy
still asserted when power opens. State bus mode and indication line. DAT0 low alone
does not prove programming: it also carries native-mode payload data.

After a clean power cut/re-power, bypass caches and read target plus neighbours.
Target must equal the complete established old or new block. A torn block is a blocker,
not a firmware workaround. Keep misses and failures; never edit the result stream
to manufacture PASS. The rig firmware and raw transaction/rail traces must be reviewable
before any physical-atomicity acceptance; they are not yet delivered.

**Run-integrity clarification (PM655 / ADR-204).** Classify target and neighbours
on every otherwise valid returned row, including non-qualifying misses. Any tear,
corruption or neighbour damage fails the run without adding qualifying-cut credit.
If accepted full payload, matching identities/readbacks and an independently
qualified method establish busy completion strictly before actual power opening
outside uncertainty U, an OLD target is run-failing `completed_write_reverted`.
Do not silently count it as a benign miss or automatically relabel it TORN.
Completed-before requires `busy_end < rail_open − U`; equality at either ±U edge
is ambiguous. Ambiguous/incomplete/electrically unqualified evidence supplies no
completed-write proof. Preserve raw observations and distinguish a method/integrity
finding from an established media defect. Normal OLD/NEW qualifying-cut outcomes
and the fixed 1,000-cut minimum stand. Circuit thresholds/timing still need
independent method review and measured controls before physical use.

From hardware/characterisation, use media_atomicity.py plan with exact --sku,
--revision, --cid, --attempts 1500 and --out plan.json; commit it, run the rig, then
media_atomicity.py judge --plan plan.json --results run.jsonl --json RESULT_PATH.
Use plan --extend for additional attempts. The script’s --help and its end-to-end
tests are the executable CLI reference. Run make -C hardware atomicity-test first.

Sustained-write command: hardware/characterisation/measure_sustained_write.py CARD_MOUNT
with exact --sku, --revision, --reader, --fill and --json RESULT_PATH.
Do not reuse the old example’s 128 GB SKU as an approved purchase.
