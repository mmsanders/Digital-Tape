## Measurements and interpretation

| Criterion | Required evidence |
|---|---|
| A-1 | Michael-approved sample set and suitable reader in hand; exact manufacturer part number, capacity, revision and CID per card |
| A-2 | Per candidate SKU/revision, at least one sustained-write run on 80%-filled media: ≥1200 MB transfer, worst 64 MB window and raw per-window data. Unfilled repeat/unit/control runs are useful screening evidence but do not replace the filled run |
| A-3 | Evaluate against C-60 end-to-end copy requirement; no automatic return to the superseded 90-minute rule |
| A-4 | Establish the reader is not the bottleneck; similar top results at its ceiling invalidate a card-speed conclusion |
| A-5 | Approved bench parts support one Route A and one Route B trial |
| A-6 | Every candidate SKU/revision: ≥1,000 qualifying cuts; zero torn/corrupt blocks or neighbour damage; identity/plan/protocol evidence below |

C-60 contains 635,040,000 PCM bytes per side. Payload alone requires 21.168 MB/s
over 30 seconds; bus/metadata/initialization and both source/destination work still
need end-to-end verification. A nominal 25 MB/s bus ceiling is not measured margin.
The existing tool reports against a 23.3 MB/s headroom bar; that threshold is
unchanged by this cleanup and is not end-to-end acceptance. The Teensy bench checks function; PC tests characterize media; production validates
the actual copy requirement. V30 is not an atomicity guarantee.

The 80% condition remains. Low logical product occupancy does not by itself prove the
flash translation layer will avoid prior writes, garbage collection or other long-tail
stalls over the card's life, and the submitted PNY sample-3 filled run passed anyway.
Four unfilled runs are retained as useful screening and negative-control data; they
are not four failures of A-2. The one filled result is a narrow observation about that
physical sample, pending identity completion and independent audit—not SKU acceptance.

## Atomicity procedure — retained independent-review requirements

Commit the plan before the run. Bind every result to SKU, revision, CID, run id and
plan digest. Count distinct qualifying trials, not rows. Planned attempts and required
qualifying cuts are separate; use an auditable plan extension if misses consume the
surplus. The judge’s 1,000 minimum cannot be reduced through operator input.

Before every cut trial establish the exact old target pattern by a completed write
and verified read. Preserve separate baselines for all four neighbours (-2, -1, +1,
+2). Missing/malformed neighbour data invalidates the run; never assume a prior
interrupted trial completed.

A cut qualifies only with evidence of all four steps: full single-block payload
transferred; accepted data-response token; observed entry into protocol busy; busy
still asserted when power opens. State bus mode and indication line. DAT0 low alone
does not prove programming: it also carries native-mode payload data.

After a clean power cut/re-power, bypass caches and read target plus neighbours.
Target must equal the complete established old or new block. A torn block is a blocker,
not a firmware workaround. Keep misses and failures; never edit the result stream
to manufacture PASS. The rig firmware and raw transaction/rail traces must be reviewable
before any physical-atomicity acceptance; they are not yet delivered.

From hardware/characterisation, use media_atomicity.py plan with exact --sku,
--revision, --cid, --attempts 1500 and --out plan.json; commit it, run the rig, then
media_atomicity.py judge --plan plan.json --results run.jsonl --json RESULT_PATH.
Use plan --extend for additional attempts. The script’s --help and its end-to-end
tests are the executable CLI reference. Run make -C hardware atomicity-test first.

Sustained-write command: hardware/characterisation/measure_sustained_write.py CARD_MOUNT
with exact --sku, --revision, --reader, --fill and --json RESULT_PATH.
Do not reuse the old example’s 128 GB SKU as an approved purchase.
