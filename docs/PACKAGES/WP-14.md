## Interface

`tapectl` already exists for disk images, per [the WP-11 contract](../WP11-CLI-CONTRACT.md).
WP-14 extends the same binary to removable media. The exact command syntax is fixed by
[`docs/WP14-CLI-CONTRACT.md`](../WP14-CLI-CONTRACT.md), issued in P2-R1 (ADR-163). The contract must cover:

- **`provision DEV`.** Write an MBR with exactly the two partitions in `tapefs` §3:
  - partition 1: FAT16 (0x0E), 16 MiB, 2 KiB clusters (approved E-1; ADR-164), holding `README.TXT`;
  - partition 2: TAPEFS (0xDA), the rest of the card.

  Then run `tape_format` on partition 2 with the label and length (C-60 by default). `tape_format`
  never sees the MBR (`engine-api` §3); a new port presents partition 2 as the engine's block device.
- **`load`, `dump`, `promote` and `verify`** on a provisioned device. They behave exactly as on an
  image, through the same port.
- **`verify DEV|IMG`.** Read-only. Checks the MBR and partition layout, both superblocks, the engine-selected valid
  indices through engine calls, and reads every referenced chunk. Exit 0 if clean; otherwise 1,
  with a named finding.
- **Device naming.** The user always names the device. `tapectl` never picks one by itself.

Port requirements. These are host-port code under `host/port/` only; nothing changes in the engine:
- **Flush is a real durability barrier:** `fsync` on Linux, `F_FULLFSYNC` on macOS (raw-device unsupported fallback per contract §6),
  `FlushFileBuffers` on Windows. Today's `dev_file` flush is a C-library `fflush`. That is fine for
  an image file but **not durable on a card**, and the whole crash-safety design depends on flush (guardrail 07).
- **64-bit byte offsets on every platform.** `dev_file` uses `fseek` with a `long`, which is 32 bits
  on Windows, and a 64 GB card's TAPEFS partition is far past 2 GiB.
- **Any batching of unflushed writes** must stay within what `tapefs` §8.1 permits. Q-P2-1(a) in
  the plan is the open question on how far the crash model covers that.

## Acceptance criteria

| # | Criterion |
|---|---|
| A1 Provision | On a disk image and on each platform named in D2, `provision` produces exactly the `tapefs` §3 layout. The computer's own OS can read partition 1 and `README.TXT`. Both sides of partition 2 mount |
| A2 Round trip | `load` a WAV, remove and reinsert the card (so nothing comes from cache), then `dump` Side A and Side B. Both are byte-identical to the input under the exact WP-11 render semantics (canonical WAV bytes and final frame; no tail tolerance). Run on the WP-11 references and on a full-length C-60 |
| A3 Durability | Flush reaches the medium on every platform. A negative control proves the test detects a port whose flush is a no-op. **Witnessed:** Michael pulls the card at ten different points during a C-60 load. Every result remounts to one of the WP-10 permitted outcomes and `verify` agrees. This is a real-world sanity check on top of WP-10, not a replacement for it |
| A4 Disk safety | `tapectl` refuses, with zero writes, any device that is: not removable or SD-class; larger than a contract-set ceiling; holding the running OS; or holding a mounted volume it did not create. It also refuses any path that is not a whole device, and any device the user did not name. Each refusal rule has a negative control, using a loop device or image made to look like the forbidden case. **This is the criterion that protects the family's computer and outranks every other** |
| A5 `verify` is read-only | The device is bound with a NULL write callback, the WP-36 pattern, so any write attempt crashes the test instead of touching the card. It detects, each with a negative control: a flipped index byte, a torn superblock, a truncated partition, a wrong partition type and an unreadable chunk |
| A6 Large media | All commands work on a 64 GB card, at addresses past 4 GiB, on every D2 platform |
| A7 Capacity | A source longer than the cartridge label is refused before any write, with exit 2 and the overage in plain words |
| A8 Engine untouched | `engine/` is byte-identical to main; Phase 1 goldens and replays are green |
| A9 Load time | Recorded, not gated: wall time to provision and load a full C-60 on a PNY card, per platform |
